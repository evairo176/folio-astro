A production computer-based testing platform that lets a school run exams end-to-end: teachers author questions (manually or with AI), students take timed exams with autosave, and grading + analytics happen automatically. The hard part isn't the CRUD — it's making exam-taking **durable and fair** under concurrent load, which drove a Redis-fronted answer store with a Postgres backstop.

## Overview

CBT digitizes the full exam lifecycle for multiple schools on one platform. A manager administers a school, teachers own their subjects/exams and grade, and students take assigned exams. Questions can be generated by AI or written by hand, exams enforce a server-authoritative timer and pass threshold, and results roll up into per-exam and per-student analytics. The system is multi-tenant (school-scoped) with role-based access control across four roles.

## Key Features

### AI Question Generation
- Generate questions automatically for an exam, plus an "Auto-tag AI" action that classifies/labels existing questions.
- Mixed formats per exam: multiple-choice (auto-graded) and essay (manual or AI-assisted grading).

### Real-Time Exam Taking (timer + autosave)
- Server-authoritative countdown timer so a client can't cheat the clock.
- Continuous autosave of in-flight answers, so a refresh, disconnect, or crash never loses a student's work.
- Per-exam config: passing score (% for certificate), max attempts (0 = unlimited retakes until pass), and open/close scheduling windows.

### Class-Based Access & Roles
- Four roles: **superadmin** (platform owner across schools), **manager** (school admin), **teacher** (own subjects/exams/grading), **student** (assigned exams only).
- Classes → subjects → exams hierarchy; students only see what's assigned to their class.

### Automatic Grading & Analytics
- Instant scoring for objective questions; essays flagged for manual/AI grading.
- Dashboards with score distribution, pass-vs-fail breakdown, per-exam performance, and item analysis ("Analisis Butir") to surface frequently-missed questions.
- Question bank with import-from-bank and shareable questions across exams.

## Architecture

- **Backend:** Go + **Echo** HTTP framework, data access via **pgx** with **sqlc**-generated type-safe queries.
- **Primary store:** PostgreSQL (`cbt` database) — users, schools, classes, subjects, exams, questions, attempts, RBAC tables.
- **In-flight answer store:** **Redis** holds answers as a student works; a flush worker persists them to Postgres, with Postgres as the durable backstop. This keeps writes fast during a live exam while guaranteeing no answer is lost.
- **Auth:** JWT access + refresh tokens, argon2id password hashing, role + permission tables for RBAC.
- **Frontend:** React + Vite + TypeScript SPA (installable PWA), bilingual exam UI.
- **Ops:** systemd-managed `cbt-api`, live at `cbt.evairo.fun`, with a daily database backup.

## Engineering Challenges & Solutions

- **Durable answers under load:** writing every keystroke straight to Postgres doesn't scale during a synchronized exam. The fix is a two-tier store — answers land in Redis instantly, a flush worker batches them to Postgres, and Postgres acts as the backstop so a Redis hiccup can't lose data. Students get instant autosave; the system gets durability.
- **Fair timing:** the exam clock is server-authoritative, not client-trusted, so closing the tab or fiddling with local time doesn't extend an exam.
- **Type-safe data layer:** sqlc generates Go types directly from SQL, eliminating a whole class of query/scan mismatches at compile time rather than runtime.
- **Deterministic question shuffling:** answer/question ordering is seeded per attempt so it's reproducible for grading and review while still varying between students.

## Quality & Verification

- Regression suites for authoring and taking flows (login, exam build, attempt, grade) run against the live API.
- A load-test harness seeds many students sharing a baked password hash to exercise concurrent exam-taking and the Redis→Postgres flush path.
- Daily automated Postgres backup; Redis configured with AOF persistence.

## Outcome

The platform runs real exams today at `cbt.evairo.fun`. The interesting engineering is invisible to the user: a student just sees a timer and an autosaving exam, while underneath a Redis-fronted, Postgres-backed pipeline guarantees their answers survive crashes and concurrency — which is exactly what an exam system has to get right.
